Finds the security holes in your code, explains them, fixes them, and proves the fix.

An agentic AI auditor for codebases. It flags vulnerabilities, writes a fix a developer can read, refactors the code on its own branch, and re-runs the scan and the tests before anyone reviews it.

See how it works Team repository (members only)

In security-sensitive tasks, about 40% of the programs GitHub Copilot wrote were vulnerable.

AI assistants now write a large share of new code, and they repeat the insecure patterns they learned from. Scanners catch many of these bugs, but they stop at a list of warnings.

Someone still has to work out which warnings are real, understand each one, write the fix, and check that the fix did not break anything else. Sentinel does that work and shows its evidence.

Pearce et al., "Asleep at the Keyboard? Assessing the Security of GitHub Copilot's Code Contributions", 2021. 1,689 programs across 89 scenarios.

How it works

Five steps, run as a loop. A patch only moves forward when the evidence says it should.

  1. Scan

    Static analysis finds candidate problems. A language model reads the code around each one and drops the false alarms.

  2. Recommend

    For every real finding: what is wrong, how it could be exploited, and the proposed fix in plain words.

  3. Refactor

    Sentinel writes the patch on its own branch and keeps the change as small as it can.

  4. Verify

    It re-runs the scan and the tests.If the finding is still there or a test fails, it goes back to step 2.

  5. A person approves

    A developer reads the explanation and the diff, then decides. Nothing merges on its own.

The report that comes with it

What a Sentinel report will look like.

Finding
SQL injection (CWE-89) and plain-text password check (CWE-256) in LoginService.login, lines 13 to 14.
Why it matters
A name such as ' OR '1'='1' -- logs in as the first user in the table, and anyone who reads the database reads every password.
Fix
A parameterised query, and a comparison against a salted bcrypt hash instead of the password itself.
Proof
The re-scan no longer reports either finding, and the login tests pass on the fix branch before the pull request opens.

What makes it different

It proves its fixes.

Every patch is re-scanned and tested before a person sees it. A fix that leaves the finding in place, or breaks a test, never reaches review.

It explains itself.

Each finding comes with the reason it is dangerous and the reason this fix closes it, in words a developer can check in a minute.

People decide.

Sentinel opens pull requests. It never merges them. Every change keeps a human owner.
